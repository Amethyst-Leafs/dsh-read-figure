# examples — 真实输出，不是手写的示意

这三个文件是 `read-figure` 在 **2026-10-17** 的真实产物，原样收录，用来说明输出长什么样。

| 文件 | 模式 | 图 | 一次调用 |
| --- | --- | --- | --- |
| [`handoff-q01.md`](handoff-q01.md) | 整图交接件 | `1.jpg`（1536×2711） | 64 s，completion 11418（思考 9294） |
| [`handoff-q02.md`](handoff-q02.md) | 整图交接件 | `2.jpg`（3094×1526） | 98.8 s，completion 18166（思考 16854） |
| [`handoff-q02-followup.md`](handoff-q02-followup.md) | 定向追问 | `2.jpg` | 23.9 s，completion 3964（思考 3199） |

生成用的命令就是这三条：

```bash
node bin/read-figure.mjs --img <figures>/1.jpg --label "第 1 题" --out examples/handoff-q01.md
node bin/read-figure.mjs --img <figures>/2.jpg --label "第 2 题" --out examples/handoff-q02.md
node bin/read-figure.mjs --img <figures>/2.jpg --label "第 2 题" \
  --question "<见该文件第二段的问题原文>" --out examples/handoff-q02-followup.md
```

## 改动了什么

每个文件只改了两处：**源图的绝对路径**和**凭证库的绝对路径**，都换成 `<本机路径>`。
其余逐字保留，包括生成时间戳、token 计数和密钥来源那一行。

## 源图不随仓库分发

这两张图属于一份真实试卷，不随仓库分发；`.gitignore` 也排除了 `fixtures/*.jpg|jpeg|png`。
所以拿不到同样的图就跑不出一字不差的同样输出——**这三个文件是记录，不是回归基线**。
要检验回归，用 `npm run check`（对着本地桩服务真跑一次 `execute`），不要去比这几个文件。

## 看什么

1. **三段式**：`一、图的结构（逐项描述）` / `二、复述` / `三、⚠ 读图置信度声明`，
   末尾跟一段给纯文本模型的执行说明。文件里**没有任何解答**——这是协议的第一条。
2. **坐标是估计值**。模型写的是「y ≈ 230」这种目测值，不是测量值；它拿不准时会自己声明。
   这正是「描述 → 复述 → 求解」三步存在的理由：先让不确定暴露出来，再拿它去解题。
3. **思考链吃掉大部分预算**。`2.jpg` 那次 completion 18166 tokens，其中 16854 是思考，
   占 **92.8%**。这就是缺省 `maxTokens` 必须远高于「正文长度」的原因——正文只有 2739 字符。
4. **定向追问只回答一处**。第三个文件不重写整份交接件，只回答「小块 A 到底是什么形状」，
   并列出两种读法各自的依据。

## 一个容易误读的地方

`read-figure` 会先对图做连通域扫描，把孤立墨块的位置、尺寸、深浅作为**请求的一部分**塞给视觉模型
（提示它「这些数字是程序测出来的，别用你的目测覆盖」）。这些数字**不会**出现在交接件里——
交接件是写给人看的描述，不是扫描报告。所以这三个例子里找不到「机械像素扫描」一节是正常的。
